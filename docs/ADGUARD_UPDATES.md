# Штатные обновления AdGuard Home

Новая установка использует проверенный официальный AdGuard Home v0.107.80.
Штатная проверка версии и обновление через административный путь `/adg-…/`
разрешены. Обновление запускает пользователь в интерфейсе AGH; установщик не
управляет последующими версиями и не обновляет AGH по расписанию.

Для существующей управляемой установки с оригинальной v0.107.79 предусмотрен
отдельный режим `--enable-agh-updates`. Он не вызывает Installation, не
переустанавливает стек и не заменяет AGH YAML шаблоном. Первоначальная версия
в `managed.json` остаётся прежней; фактическую версию проверяют по бинарнику.
Разблокировка сама по себе не устанавливает v0.107.80.

Команда принимает только узнаваемое целостное управляемое состояние с
loopback DNS/admin, известным nginx snippet и собственной systemd-службой.
Поддерживаются оба ранее выпускавшихся nginx snippet: исторический только с
`/dns-query` и вариант с ClientID. Их содержимое при разблокировке сохраняется.
Неизвестные конфигурации и незавершённая смена доменов блокируют операцию.
Применяется общий operation lock. Устанавливаются согласованные AGH/Backup
helper'ы из одной фиксированной ревизии с проверкой SHA-256 и доверенный ключ
AGH с fingerprint `28645AC9776EC4C00BCE2AFC0FE641E7235E2EC6`.
При необходимости устанавливаются только зависимости проверки подписи
`gnupg`/`gpgv`; полное обновление ОС не выполняется.

Изменяются разрешение обновлений и соответствующий аргумент службы AGH.
Проверяются DNS, DoH и интерфейс через nginx. Исходно остановленная служба
после временной проверки снова останавливается; её autostart не меняется.
Повторный запуск безопасен. При ошибке записи восстанавливаются затронутые
файлы и прежнее состояние AGH; при неподтверждённом откате сохраняются
приватные оригиналы с сообщением об ошибке.

Installation — новая установка или полная переустановка, а не обновление
существующего VPS. Не используйте её для разблокировки AGH.

## Команда для включения обновлений

Для существующей управляемой установки используйте опубликованный релиз
**v2.4.2**. Версия v2.4.1 содержит ошибку проверки сетевых сокетов AdGuard Home,
а историческая v2.4.0 не поддерживает эту операцию.

```bash
sudo bash -c 'set -euo pipefail; umask 077; d=$(mktemp -d); trap '\''rm -rf -- "$d"'\'' EXIT; cd "$d"; u=https://github.com/xPROMSx/3x-ui-auto-nginx/releases/download/v2.4.2; curl -fLsS --connect-timeout 15 --max-time 120 "$u/x-ui-latest.sh" -o x-ui-latest.sh; curl -fLsS --connect-timeout 15 --max-time 120 "$u/x-ui-latest.sh.sha256" -o x-ui-latest.sh.sha256; sha256sum --check --strict x-ui-latest.sh.sha256; bash ./x-ui-latest.sh --enable-agh-updates'
```

Оба файла загружаются по HTTPS из одного фиксированного релиза. Проверка
sidecar обязательна до запуска. Официальный release builder закрепляет
в asset точный commit SHA; оба helper'а берутся из этого SHA, а их SHA-256
дополнительно закреплены в скрипте. Не подменяйте источник текущей `main`.

## Backup/Restore v3 и границы совместимости

Формат Backup остаётся v3. Оригинальная историческая `.79` проверяется по
закреплённому SHA-256. Более новые бинарники требуют корректной подписи
производителя; проверка выполняется до запуска бинарника из архива.
Доверенный ключ и `AdGuardHome.sig` сохраняются в дереве AGH и в Backup.
Upstream updater переносит supporting files, включая подпись, и в Linux
перезапускает новый бинарник через `exec` внутри службы.

Restore сохраняет состояние самого архива, включая прежний запрет обновлений.
После восстановления старого архива при необходимости снова примените ту же
команду разблокировки. Пользовательские данные и настройки не мигрируются
шаблоном новой установки.

Будущие официально подписанные версии принимаются без точного совпадения с
первоначальной версией, пока сохраняются поддерживаемые контракты конфигурации,
API, локальной изоляции и службы. Подпись подтверждает производителя, но не
совместимость всех будущих версий. При несовместимом изменении upstream
проверка должна безопасно отказать до замены рабочего состояния.
