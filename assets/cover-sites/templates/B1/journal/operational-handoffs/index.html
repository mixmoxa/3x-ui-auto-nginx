A handoff should preserve the unfinished question.

The most useful handoff makes it possible to act without guessing what has already been attempted.

Editorial team · {{DATE_3}}

In this noteLead with the current stateSeparate facts from interpretationsRecord actions and their effectsMake the next decision explicit

Lead with the current state.

State whether the service is healthy, degraded or unavailable, and name the affected operation. Include the time range of the observation and the source of the evidence. A sequence of chat messages can document a conversation while leaving the actual state ambiguous. The reader should find the condition that exists now before the history of how it was discovered. When a metric is delayed or incomplete, state that limitation immediately.

Separate facts from interpretations.

A failed request, a changed configuration and an upstream alert are observations. Saying that one caused another is a hypothesis until it has been checked. Keep those categories apart. Link to a short command output or log extract when it is safe to do so, but avoid sending credentials and personal data. An honest list of unresolved possibilities saves time because a new responder can test them instead of inheriting an unsupported conclusion.

Record actions and their effects.

For each meaningful action, say what was changed and what happened afterward. A restart that did not restore a connection is still useful information. Include the path to revert the action when it changes persistent state. Do not repeat an experiment simply because it produced no visible improvement; ask whether the absence of change narrowed the cause. This encourages one deliberate next test instead of an escalating sequence of guesses.

Make the next decision explicit.

End with the smallest useful next check, its expected result and the condition that would change the plan. If the next step can interrupt users or lose data, identify the approval required before it happens. Keep the handoff short enough to read under pressure, with deeper references available separately. A responder who understands both the current state and the uncertainty can continue safely without needing a live briefing.

Further reading

Continue with the journal index, or explore the overview for the wider context. Write down the affected operation, the available evidence and the decision still open. Keep any untested interpretation separate from the observations. This journal describes approaches to engineering review, not a report about a particular customer system or a deployed service.
