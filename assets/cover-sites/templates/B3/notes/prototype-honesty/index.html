NOTES / ORIGINAL STUDIES

Show the boundary of a prototype.

A convincing prototype should explain what is real, what is simulated and what has not been tested.

Editorial team · {{DATE_2}}

01 / STUDIO NOTE

Label the actual behaviour

A local button that rearranges sample cards is an interaction. It is not evidence of a synchronized database or a working subscription. Give controls visible results and avoid presenting a disabled form as though it will accept a request. If an interface needs a login service that does not exist, show the idea as a labelled concept or remove the entry point from the public page. Visitors should not have to discover the limitation by repeatedly clicking.

02 / STUDIO NOTE

Keep content separate from claims

A fictional project name can help explore a visual identity. It should not become a fabricated client endorsement, staff list or case study metric. Describe the decisions and their constraints instead. In a self-initiated design study, a page can show possible navigation, hierarchy and error states without suggesting that the system is deployed. That distinction keeps the work useful to readers interested in the design method rather than the appearance of commercial success.

03 / STUDIO NOTE

Prototype the failure state

A working demonstration should show what happens when input is empty, incorrect or unexpectedly long. If a tool has no server, say where its data is processed. Static explanatory content is preferable to a fake loading animation that can never complete. A prototype does not need every production feature, but the controls it presents should behave consistently within their stated boundary. Test with a keyboard and a small screen, not only a pointer in a wide mock-up.

04 / STUDIO NOTE

Publish observations carefully

Document which interactions were exercised and what the test environment was. Avoid calling a design accessible or fast because it looked clean in one browser. Real accessibility review includes keyboard operation, semantics, contrast and users with different needs. This note is an independent exploration, and its examples are hypothetical. That is a legitimate result when the limitations are visible and the next questions are specific.

05 / READING

Related work

Continue with the notes index, or explore the overview for the wider context. Apply the question to an original sketch or a small piece of sample content. Check reading order with a keyboard and a narrow viewport before making claims about usability. These conceptual studies present design reasoning, not commissioned work or validated visitor results.
