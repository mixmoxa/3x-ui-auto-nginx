WORKSPACE / READING

Review work without creating another meeting.

A review is valuable when it produces a clearer next step, not when it generates a longer status presentation.

NOTE 01

Review outcomes before activity

Open with the completed result and the evidence that it works. A page published to the correct address is an outcome; several hours spent adjusting headings is activity. Both may matter during the work, but they answer different questions. If the outcome is missing, identify the smallest remaining obstacle. Avoid using a percentage complete as a substitute for a runnable or readable result. It can hide uncertainty precisely when decisions are most useful.

NOTE 02

Inspect the queue as a reader

Look at each unfinished item and ask whether its value is still obvious from the title and description. Rewrite vague items as outcomes or close them when they no longer serve the current goal. A queue is a tool for deciding what to do next, not a permanent record of every thought. Keep important reasoning in decision notes, where it can be found without carrying a task forever. This separation reduces the friction of choosing work.

NOTE 03

Expose blockers without drama

Name a blocker as a fact that prevents a specific action. “Waiting for confirmation of the output format” is useful; “the project is blocked” offers little guidance. Record who or what can resolve it and what can proceed independently. When a dependency is external, avoid inventing dates that imply certainty. Good status leaves another person able to make the next decision without asking for a second explanation.

NOTE 04

End with a shorter plan

Choose the next one or two verifiable results. Keep ongoing maintenance separate from new features so urgent repairs do not disappear under larger ideas. A small retrospective question is enough: which assumption was wrong, and what would have exposed it earlier? Write the answer down only when it changes how work should be done. A review that removes obsolete tasks and clarifies a decision has done useful work, even if it produces no new feature.

Further reading

Continue with the guides index, or explore the overview for the wider context. Try the method on a small unfinished task before using it for a larger project. Keep the original explanation next to the revised one, and record which decision became clearer. A useful note should remain understandable to someone who was not present for the discussion.
