REFERENCE / METHOD

Keep examples reproducible

The examples use conventional HTTP semantics rather than an invented private API. You can examine responses from a server you control with curl -I and curl -v.

Always test real applications as well as static responses: reverse proxies can change which headers and status codes reach clients.

Begin with the response you can actually observe. Status codes answer one question, media types answer another and redirect headers may move a request to a different resource. Inspect those elements separately before changing a configuration. The additional chapters cover caching, representations and location changes. Each guide includes a method for testing the behaviour on a service you control.
