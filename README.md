**3X-UI AUTO NGINX** - бесплатный установщик [3x-ui](https://github.com/MHSanaei/3x-ui) и Xray для вашего собственного VPS. Вы указываете два домена и запускаете одну команду. Остальное делает скрипт: ставит Nginx и HTTPS-сертификаты, настраивает подключения REALITY, XHTTP и Hysteria2, готовит ссылку подписки для ваших устройств и создаёт сайт-прикрытие. Дальше всё управляется из меню: смена доменов, резервные копии, Каскад из двух серверов, личный DNS-сервер.

## 🚀 Быстрый старт

**Что понадобится:**
- VPS с чистой Ubuntu 24.04, 26.04 или Debian 13 и доступ по SSH под **root**.
- Два домена или поддомена (один для панели, другой для REALITY) с DNS-записями на IP-адрес VPS.
- Доступные из интернета входящие порты: TCP **80** и **443**, UDP **443**. Если включите DoT, ещё TCP **853**.

Команда установки (выполните на VPS):

```bash
curl -fSL https://github.com/xPROMSx/3x-ui-auto-nginx/releases/latest/download/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

После запуска выберите **1 — English** или **2 — Русский**. Затем откроется главное меню:

- **1 — Установка:** настройка сервера с нуля или полная переустановка.
- **2 — Смена доменов:** изменение домена панели, REALITY или обоих без переустановки.
- **3 — Резервные копии:** создание, просмотр и восстановление Backup.
- **4 — Telegram Web Proxy Manager:** запуск или установка отдельного менеджера Telegram-прокси.
- **5 — Каскад:** настройка цепочки из двух серверов, проверка состояния и отключение.
- **6 — Данные моего сервера:** адреса панели, подписок и AdGuard Home и логины. Пункт только показывает данные, ничего не меняет и не показывает пароли.
- **0 — Выход.**

Забыли адрес панели или DoH? Откройте пункт 6.

Для работы с меню нужен интерактивный SSH-терминал.

<details>
<summary><strong>Резервная загрузка — если GitHub Releases недоступен</strong></summary>

**Ветка `main` содержит альфа-версию проекта.** Устанавливать её не рекомендуется. Используйте стабильный релиз по основной команде выше.

```bash
curl -fSL https://raw.githubusercontent.com/xPROMSx/3x-ui-auto-nginx/main/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

</details>

<a id="installation-vs-update"></a>

> [!CAUTION]
> **Установка — не обновление!**
>
> Повторный запуск скрипта **без параметров** открывает менеджер, а не переустанавливает сервер. Но пункт **«Установка»** предназначен для чистого VPS или полной переустановки.
>
> Если обнаружена существующая установка, скрипт предупредит об удалении управляемых данных и запросит точное подтверждение **YES**. При переустановке заменяются база 3X-UI и конфигурация nginx. Дополнительно:
> - если у вас был XTLS Vision, а в новой установке его не будет (или вы выберете другой домен), удаляется сертификат старого домена Vision, который создал установщик. Об этом скрипт предупредит перед запросом YES;
> - если был AmneziaWG, а в новой установке его не будет, закрывается порт 8443/udp (отдельного предупреждения об этом нет).
>
> **Заранее сохраните Backup вне VPS.**
>
> **«Смена доменов»** и **«Резервные копии»** — отдельные операции, не требующие переустановки панели.

<details>
<summary><strong>Как обновляться?</strong></summary>

- **3X-UI и Xray:** используйте штатные средства панели. Совместимость новых версий с конфигурацией проекта может быть ещё не проверена.
- **3X-UI AUTO NGINX:** обновление установленного стека поверх существующего не поддерживается. Для доступа к возможностям нового менеджера, например к пункту **5 — Каскад**, можно скачать актуальный скрипт и выбрать нужную операцию. Скрипт проверит совместимость установленной конфигурации.
- **Backup / Restore:** сохраняет и восстанавливает данные, но не обновляет стек.
- **Что даёт версия 2.7.0 уже работающему серверу:** пункт **6 — Данные моего сервера** показывает то, что удаётся прочитать на ранее установленных серверах. Случайный адрес DoH, вопрос про дополнительные подключения и DoT доступны только при новой установке. На старых серверах WebSocket и Trojan gRPC остаются как были, а DoH работает по прежнему адресу `/dns-query`.

**Не выбирайте «Установка» ради обновления!** nginx, ядро Linux и другие системные пакеты обновляются средствами ОС.

</details>

Основных вопросов семь, у некоторых есть уточнения. Для большинства достаточно ответов по умолчанию.

<a id="3--enhanced-vps-security"></a>

### 3. 🔐 Расширенная безопасность VPS

> `Усилить безопасность VPS? [Y/n]:`

*Рекомендуется неопытным пользователям · Включена по умолчанию (`Y`)*

Установщик настроит Fail2ban для защиты SSH, зашифрованный DNS самого сервера (DoT) и автоматические обновления безопасности. При подходящих условиях также создаётся swap-файл размером 1 ГиБ — независимо от выбора дополнительной защиты.

**Перед включением ознакомьтесь с параметрами ниже**, особенно с расписанием автоматических перезагрузок.

<details>
<summary>🔐 <strong>Подробное описание настроек безопасности</strong></summary>

Дополнительная защита включается при выборе `Y`. Подготовка swap выполняется независимо от этого выбора:

- **Swap 1 ГиБ.** Если swap отсутствует, файловая система поддерживается и свободно не менее 4 ГиБ, установщик создаст и активирует swap-файл. Существующие настройки swap не изменяются. Если условия не выполнены, этот этап будет пропущен без остановки установки.
- **Защита SSH — Fail2ban.** Ограничение повторных неудачных попыток входа с учётом фактических SSH-портов. Существующие параметры SSH-аутентификации не изменяются.
- **Шифрованный DNS самого сервера (DoT).** Это защита собственных DNS-запросов сервера, а не DNS-сервер для ваших устройств (он описан в разделе про AdGuard Home). Глобальные DNS-серверы Cloudflare и Google используют строгий DNS-over-TLS через `systemd-resolved`. DNS-маршруты и search domains интерфейсов/VPN сохраняются; их запросы могут оставаться незашифрованными. Если подготовка DoT не удалась, но исходный DNS успешно восстановлен, установка основного стека, Fail2ban и автоматических обновлений продолжается независимо от DoT; итоговый статус сообщает об отказе, код завершения ненулевой.
- **Автоматические обновления безопасности.** Обновление списков пакетов — в 02:30, установка обновлений — в 02:50.
- **Автоматическая перезагрузка — 04:38.** Если после обновлений системе потребуется перезагрузка, она выполняется в указанное время, **в том числе при активных пользовательских сеансах**. Это может прервать действующие подключения.

Время указано по локальному часовому поясу VPS.

Перед изменениями выполняются проверки совместимости существующих настроек. При ошибках конфигурации безопасности предусмотрен контролируемый откат.

**Важно:** установщик не отключает SSH-вход по паролю и не заменяет полноценное администрирование сервера. Рекомендуется настроить вход по SSH-ключам и затем самостоятельно отключить парольную аутентификацию.

</details>

### 4. 🧩 Дополнительные подключения

> `Настроить дополнительные подключения? [y/N]:`

*По умолчанию отключено (`N`)*

По умолчанию устанавливаются и настраиваются VLESS Reality, VLESS XHTTP и Hysteria2. Дополнительные подключения: VLESS WebSocket, Trojan gRPC, VLESS TCP/TLS (XTLS Vision), AmneziaWG, XHTTP для CDN.

> [!WARNING]
> Эти подключения могут работать не везде: это зависит от страны и провайдера. Используйте их на свой риск. Если не уверены, ответьте `N`.

При ответе `N` ни одно из них не создаётся, и следующие вопросы (4.1-4.4) не задаются. При ответе `y` установщик спросит о каждом по очереди.

#### 4.1. WebSocket и Trojan gRPC

> `Настроить устаревшие подключения VLESS WebSocket и Trojan gRPC? [y/N]:`

Оба подключения вместе: при `y` они создаются включёнными, при `N` не создаются вовсе.

<details>

Установщик создаёт серверное подключение, но не генерирует клиентов AmneziaWG автоматически.

Конфигурация включается в **Backup / Restore v3** вместе с необходимыми настройками firewall.

</details>

<a id="xhttp-cdn"></a>

#### 4.4. 🌐 VLESS + XHTTP для CDN

> `Добавить дополнительное подключение XHTTP, совместимое с CDN? [y/N]:`

*Дополнительное подключение · По умолчанию не устанавливается (`N`)*

Создаётся отдельное VLESS-подключение с транспортом XHTTP в режиме packet-up, предварительно настроенное для работы через CDN. Подключение создаётся выключенным в панели 3X-UI.

Используется существующий HTTPS-домен панели, поэтому дополнительный домен и сертификат не требуются. После включения подключение можно использовать напрямую, без CDN.

Для работы через CDN пользователь самостоятельно настраивает своего CDN-провайдера и изменяет параметры Host в 3X-UI. Установщик не настраивает CDN, а предоставляет готовый серверный профиль для дальнейшего использования.

<a id="warp-ru"></a>

### 5. 🌐 Российские сайты через Cloudflare WARP

> `Скрыть IP вашего VPS от российских сайтов через Cloudflare WARP? [Y/n]:`

*Дополнительная маршрутизация · В русском меню включена по умолчанию (`Y`), в английском выключена (`N`)*

Если планируете использовать этот VPS как входной сервер Каскада, выберите `N`. На входном сервере WARP несовместим с Каскадом, на выходном - разрешён.

При выборе `Y` установщик настроит Cloudflare WARP (MASQUE), чтобы российские сайты и некоторые сетевые сервисы видели IP-адрес Cloudflare вместо IP вашего VPS. Это необходимо для защиты IP вашего VPS.

Настройка действует только для трафика, проходящего через VPS. Если приложение обращается к сайту напрямую, WARP на сервере на него не влияет.

При включении функции установщик регистрирует устройство в Cloudflare и принимает условия использования сервиса.

Если настройка WARP не удалась, установка продолжится без него, а итоговый отчёт сообщит о частичном результате. При неподтверждённом откате необходимо проверить работу Xray в панели.

<details>
<summary>ℹ️ <strong>Какие сайты направляются через WARP и как проверить настройку</strong></summary>

Установщик добавляет в конфигурацию Xray выходящее подключение `warp-masque` и три правила:

- **WARP - RU:** российские домены из `geosite:category-ru`.
- **WARP - RU2:** IP-адреса из `geoip:ru`.
- **WARP - RU3:** `ipify.org`, `ifconfig.me`, `checkip.amazonaws.com`, `ipapi.is`, `iplocate.io`, `ip.sb` и `2gis.com`.

Правила добавляются в конец списка маршрутизации. Более ранние правила сохраняют приоритет. Это не отдельный профиль для клиента и не системный VPN: маршрутизация работает внутри Xray.

После установки проверьте в панели 3X-UI раздел **Xray → Outbounds** (подключение `warp-masque`) и **Xray → Routing** (три правила с названиями выше). Настройки сохраняются в Backup v3 вместе с конфигурацией 3X-UI.

</details>

### 6. 🛡️ AdGuard Home + DNS-over-HTTPS и DNS-over-TLS

> `Установить и настроить AdGuard Home? [y/N]:`

*Дополнительный DNS-сервер · По умолчанию отключён (`N`)*

Персональный DNS-сервер с блокировкой рекламы и отслеживания, управлением клиентами и защищёнными DNS-запросами. Телефоны и компьютеры подключаются к нему по DoH, а при выборе DoT при установке ещё и по DoT (например, через системную настройку Android «Частный DNS»).

<details>
<summary>ℹ️ <strong>Подробнее об AdGuard Home и настройке доступа</strong></summary>

Дополнительный домен не требуется.

После установки будут доступны:

- **Панель AdGuard Home:** `https://panel.example.com/adg-.../`, индивидуальный случайный путь.
- **DNS-over-HTTPS:** `https://panel.example.com/dns-XXXXXXXXXXXX`. Часть `dns-XXXXXXXXXXXX` создаётся случайно при каждой установке.
- **DNS-over-TLS** (если выбран): адрес `panel.example.com`, порт 853.

Адреса показываются в итоговом отчёте установки, а позже в пункте **6 — Данные моего сервера**. Пароль AdGuard Home показать нельзя: сохраните его при установке.

Публичные порты **53** (TCP и UDP) не открываются. Ради AdGuard Home открывается только порт **853**, и только если вы включили DoT. Конфигурация и данные AdGuard Home сохраняются в **Backup / Restore v3**. На серверах, установленных до 2.7.0, DoH остаётся по адресу `https://panel.example.com/dns-query`.

**⚠️ Рекомендация по безопасности**

Случайный адрес DoH труднее подобрать, но он хранится в настройках ваших устройств. Поэтому для личного VPS по-прежнему рекомендуем отдельный [ClientID](https://adguard-dns.io/kb/ru/adguard-home/clients/#clientid) для каждого устройства.

В интерфейсе AdGuard Home откройте **Настройки → Настройки DNS → Настройки доступа → Разрешённые клиенты** и укажите созданные ClientID. IP-адреса и подсети добавлять не нужно. Единственное исключение: адрес `127.0.0.1`, если вы используете DoT (см. ниже).

Используйте DoH-адреса вида:

`https://panel.example.com/dns-XXXXXXXXXXXX/<ClientID>`

После настройки запросы без разрешённого ClientID будут отклоняться. Используйте длинные случайные идентификаторы. Подробнее: [официальные рекомендации AdGuard Home](https://adguard-dns.io/kb/ru/adguard-home/running-securely/).

Если вы включили DoT, учтите: по DoT ClientID не передаётся, поэтому после включения списка разрешённых клиентов DoT перестаёт работать, запросы отклоняются. Чтобы он снова заработал, добавьте `127.0.0.1` в разрешённые клиенты. Тогда DoT будет принимать запросы от любого, кто знает адрес сервера, как и сейчас без списка.

Начиная с **v2.4.1**, на новых установках проверка и установка обновлений AdGuard Home доступны прямо в его веб-интерфейсе. Если AdGuard Home установлен нашим скриптом до **v2.4.1**, включите эту возможность одной командой на VPS:

```bash
sudo bash -c 'set -euo pipefail; umask 077; d=$(mktemp -d); trap '\''rm -rf -- "$d"'\'' EXIT; cd "$d"; u=https://github.com/xPROMSx/3x-ui-auto-nginx/releases/download/v2.4.2; curl -fLsS --connect-timeout 15 --max-time 120 "$u/x-ui-latest.sh" -o x-ui-latest.sh; curl -fLsS --connect-timeout 15 --max-time 120 "$u/x-ui-latest.sh.sha256" -o x-ui-latest.sh.sha256; sha256sum --check --strict x-ui-latest.sh.sha256; bash ./x-ui-latest.sh --enable-agh-updates'
```

</details>

#### 6.1. DNS-over-TLS (DoT)

> `Включить DNS-over-TLS (DoT) для ваших устройств? [y/N]:`

Нужен в первую очередь для Android: настройка «Частный DNS» принимает только имя хоста и работает по DoT. Если эта настройка вам не нужна, оставьте `N`.

- Доступно только при новой установке, вместе с AdGuard Home.
- Сервер принимает DoT по адресу `panel.example.com`, порт **853**. Правило UFW для порта добавляется автоматически, используется сертификат домена панели.
- **Порт 853 открыт для всего интернета.** ClientID по DoT не передаётся, поэтому DoT-сервер доступен любому, кто знает адрес. Чтобы один клиент не перегружал сервер, число одновременных подключений с одного IP-адреса ограничено (примерно 50).
- В журнале AdGuard Home запросы по DoT видны с адресом `127.0.0.1`: они приходят через Nginx на этом же сервере, поэтому отдельные устройства в журнале по DoT не различаются.
- Если в AdGuard Home включён список разрешённых клиентов, DoT перестаёт работать. Как это исправить, написано выше, в описании ClientID.
- Настройки DoT сохраняются в Backup / Restore v3 и учитываются при смене доменов.

**Как подключить Android.** В настройках найдите «Частный DNS», выберите режим с именем хоста и введите домен панели.

**Как отключить DoT.** На сервере от root выполните команду:

```bash
ufw delete allow 853/tcp
```

Порт 853 закроется, остальное продолжит работать как раньше. Полностью убрать DoT можно только переустановкой сервера.

## 🌐 Смена доменов

В главном меню выберите **2 — Смена доменов**. Можно заменить домен панели, REALITY или оба сразу без переустановки. Новые DNS-записи должны указывать на VPS; для получения сертификатов необходим доступ к TCP/80. Домены должны различаться между собой и с доменом Vision.

Поддерживаются только распознанные конфигурации проекта, включая совместимые установки v2.1.7. При ошибке **не удаляйте Backup и данные восстановления**. <a id="backup--restore"></a>

## 💾 Backup / Restore

В главном меню откройте **3 — Резервные копии**, чтобы создать Backup, просмотреть список архивов или выполнить Restore. Резервную копию можно использовать после переустановки ОС или для переноса на другой VPS. Для восстановления должны совпадать операционная система, её версия и архитектура процессора. На свежем VPS Restore из меню сам дождётся конца автоматического обновления системы (до 60 минут); в это время не перезагружайте сервер.

Для работы через командную строку доступны команды (от root):

```bash
# Создать новую резервную копию
x-ui-backup backup

# Показать доступные копии
x-ui-backup list

# Восстановить выбранную копию
x-ui-backup restore /var/backups/x-ui/<archive>.tar.gz
```

Архивы сохраняются в `/var/backups/x-ui/`.

> **Backup содержит чувствительные данные:** базу клиентов, пароли и приватные ключи сертификатов. Храните копию **вне VPS** и восстанавливайте только доверенные архивы.

Если Restore невозможен, файлы можно аварийно извлечь без установки пакетов и запуска служб. Нужны только Bash, Python 3 и доступ к архиву и месту извлечения; root не требуется:

```bash
x-ui-backup extract /path/to/archive.tar.gz ./recovered-backup
```

Каталог должен быть новым; исходные пути сохраняются под `files/`, ссылки пропускаются. Данные содержат секреты — не копируйте их поверх работающего сервера без проверки.

<a id="cascade"></a>

## 🔗 Каскад из двух серверов

Каскад соединяет два VPS проекта 3X-UI AUTO NGINX в одну цепочку: устройства подключаются к входному серверу, а в интернет выходят через выходной. Каскад может быть полезен, если у вас возникают проблемы с подключением к VPS или нужен выход в интернет через сервер в другой стране.

**Клиент → Входной VPS → Выходной VPS → Интернет**

Российские сайты и российские IP-адреса открываются прямо со входного сервера (это можно отключить после настройки в правилах маршрутизации входного VPS). Остальной трафик, который не поймали другие правила маршрутизации, идёт через выходной сервер.

Настройка выполняется в главном меню, пункт **5 — Каскад**. Править конфигурации вручную не нужно.

<details>
<summary><strong>Как настроить Каскад, проверить его работу и отключить</strong></summary>

### Что потребуется

- Два VPS с работающим 3X-UI AUTO NGINX.
- Логин и пароль панели 3X-UI каждого сервера.
- Актуальный установщик с пунктом **5 — Каскад**.
- На входном сервере не должен быть настроен WARP (его можно удалить вручную).

### 1. Создать ключ на выходном сервере

На VPS, через который планируете выходить в интернет, запустите актуальный установщик.

Выберите **5 — Каскад → 1 — Создать ключ (выходной сервер)**.

Введите логин и пароль от панели 3X-UI. Они вводятся скрыто и нигде не сохраняются. Менеджер создаст специального клиента `cascade` в существующем REALITY-подключении и покажет ключ-ссылку, начинающуюся с `vless://`.

Скопируйте эту ссылку. Она понадобится для подключения второго сервера.

**Не публикуйте ключ-ссылку:** по ней можно подключиться к созданному клиенту.

Существующие клиенты не изменяются.

### 2. Подключить входной сервер

Теперь откройте актуальный установщик на VPS, к которому подключаются ваши устройства.

Выберите **5 — Каскад → 2 — Подключить выходной сервер (входной сервер)**.

Введите логин и пароль панели 3X-UI (они тоже нигде не сохраняются), затем вставьте ключ-ссылку, полученную на первом шаге. При вставке ключ виден на экране и нигде не сохраняется.

Менеджер проверит соединение с выходным сервером. Если проверка пройдёт, он создаст подключение `cascade-exit` и три правила маршрутизации `CASCADE`.

Российские сайты и российские IP-адреса будут направляться напрямую со входного сервера, остальной подходящий трафик - через выходной.

**При применении настроек соединения пользователей могут прерваться на несколько секунд.** Если настройка не пройдёт проверку, менеджер попытается вернуть прежнюю конфигурацию и сообщит результат.

Существующие клиентские подключения и подписки продолжают использоваться, создавать новые специально для Каскада не нужно.

### 3. Проверить состояние

На каждом сервере откройте **5 — Каскад → 3 — Состояние**.

Менеджер запросит логин и пароль панели, как и в других действиях.

Менеджер покажет, настроена ли на этом сервере входная или выходная роль и работает ли Xray. Эта проверка ничего не изменяет.

### 4. Отключить Каскад

Откройте **5 — Каскад → 4 — Отключить** на нужном VPS.

**На входном сервере** менеджер предложит удалить подключение `cascade-exit` и три правила `CASCADE`. Остальные подключения и правила панели сохранятся.

**На выходном сервере** будет удалён только клиент `cascade`. После этого все входные серверы, использующие его ключ, потеряют связь с этим выходом.

Каждое отключение требует отдельного подтверждения. Применение изменений на входном сервере может ненадолго прервать соединения пользователей.

### Что нужно знать

- **WARP:** на входном сервере несовместим с Каскадом. Если WARP установлен, удалите его подключение и правила через панель 3X-UI перед настройкой Каскада. На выходном сервере WARP разрешён.
- **AmneziaWG:** подключения этого типа не передаются через выходной сервер.
- **Правила маршрутизации:** существующие правила с более высоким приоритетом могут направлять часть трафика в обход выходного сервера. Менеджер предупредит об этом.
- **Недоступность выхода:** если выходной сервер перестанет работать, трафик, направленный через него, тоже перестанет проходить. Автоматического резервного выхода нет.
- **QUIC через Vision:** UDP/443 не проходит через такой Каскад.
- **Смена доменов:** после смены доменов на выходном VPS потребуется заново подключить его на входном сервере.

### Резервные копии

Backup v3 сохраняет настройки Каскада. После восстановления на входном сервере эти настройки сохраняются вместе с остальными данными 3X-UI.

Работа Каскада проверена на двух реальных VPS с REALITY, XHTTP и Hysteria2. Совместимость со всеми клиентскими приложениями и конфигурациями пока не подтверждена.

Если обнаружите ошибку, [сообщите о ней на GitHub](https://github.com/xPROMSx/3x-ui-auto-nginx/issues).

</details>

## 🔐 Безопасность

Служебные интерфейсы не открываются напрямую в интернет: панель, подписки и дополнительные сервисы доступны через nginx и HTTPS, а внутренние порты остаются локальными. Ради служебного сервиса открывается только порт 853, и только если вы сами включили DNS-over-TLS (DoT). Порты самих подключений открыты по своей природе, через них подключаются ваши устройства: TCP и UDP 443, а при выборе AmneziaWG ещё UDP 8443.

**Не уверены, как самостоятельно защитить VPS?** При установке можно включить расширенную настройку безопасности. Установщик автоматически настроит защиту SSH от перебора паролей, шифрованный DNS самого сервера и обновления безопасности. Перед включением ознакомьтесь с подробным описанием и расписанием ночных перезагрузок в разделе «Быстрый старт».

**Важно:** не забывайте защищать сам доступ к серверу. Используйте SSH-ключи, а после проверки входа по ключу отключите аутентификацию по паролю. Установщик не отключает её автоматически.

## ⚙️ Технические подробности и совместимость

- **ОС:** Ubuntu 24.04, Ubuntu 26.04 и Debian 13.
- **UFW:** разрешаются 80/tcp, 443/tcp и 443/udp (8443/udp - при выборе AmneziaWG, 853/tcp - при выборе DoT). При установке UFW включается только после проверки SSH-доступа; если сделать это безопасно нельзя, остаётся выключенным с предупреждением. После Restore через меню его можно включить **только по отдельному выбору** и после проверок безопасности; обычная команда `x-ui-backup restore` UFW не включает.
- **Сертификаты:** Let's Encrypt webroot и `certbot.timer` продлевают сертификаты автоматически, без остановки nginx.
- **Версия 3x-ui:** по умолчанию устанавливается последняя версия, тщательно протестированная на совместимость с 3X-UI AUTO NGINX. После установки вы можете самостоятельно обновить 3x-ui штатными средствами панели, но совместимость новой версии с нашей конфигурацией может быть ещё не подтверждена. Другой стабильный релиз можно явно выбрать через `-version <tag>` (минимальная поддерживаемая версия — v3.8.0); установщик предупредит о неподтверждённой совместимости.

<a id="recovery-on-a-new-vps"></a>

### Восстановление на новом VPS

Нужны те же ОС, версия и архитектура, что у копии. При смене IP VPS обновите DNS-записи доменов. Не запускайте `x-ui-latest.sh` — установите только утилиту и восстановите доверенный архив:

```bash
curl -fSL https://raw.githubusercontent.com/xPROMSx/3x-ui-auto-nginx/main/assets/backup/x-ui-backup.sh -o /tmp/x-ui-backup
install -o root -g root -m 0755 /tmp/x-ui-backup /usr/local/bin/x-ui-backup
rm -f /tmp/x-ui-backup
x-ui-backup restore /root/<archive>.tar.gz
```

SSH, настройки ОС и базовый firewall остаются ответственностью администратора. Для архивов v2 нужна утилита из соответствующего старого релиза.
