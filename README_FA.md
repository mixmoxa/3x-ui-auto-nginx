**3X-UI AUTO NGINX** نصب‌کننده‌ای رایگان برای راه‌اندازی [3x-ui](https://github.com/MHSanaei/3x-ui) و Xray روی VPS شخصی شماست. این ابزار Nginx، گواهی‌های HTTPS، اتصال‌های REALITY، XHTTP و Hysteria2، اشتراک‌ها و ابزارهای عیب‌یابی را پیکربندی می‌کند. از طریق مدیر تعاملی می‌توان سرور را نصب کرد، دامنه‌ها را تغییر داد و Backup/Restore v3 را مدیریت کرد. XTLS Vision، AmneziaWG 3.1 و AdGuard Home همراه با DNS-over-HTTPS (DoH) نیز به‌صورت اختیاری در دسترس‌اند.

**فراتر از نصب معمولی 3x-ui:** نصب‌های تازه برای پنل و REALITY دو وب‌سایت چندصفحه‌ای متفاوت با ظاهر شخصی‌سازی‌شده دریافت می‌کنند. در دامنه REALITY، درخواست‌های معمول HTTPS روی TCP و درخواست‌های HTTP/3 بدون احراز هویت روی UDP همان وب‌سایت را نمایش می‌دهند. همه‌چیز با Nginx و Xray موجود کار می‌کند و به Docker یا وب‌سرور اضافی نیازی نیست. تغییرات v2.4.0 به‌طور خودکار روی VPSهای نصب‌شده از قبل اعمال نمی‌شوند.

## 🚀 شروع سریع

رکوردهای DNS **دو دامنه** را به نشانی IP سرور VPS خود هدایت کنید: یکی برای پنل و دیگری برای REALITY. با SSH و کاربر **root** وارد شوید و مطمئن شوید پورت‌های TCP **80 و 443** و پورت UDP **443** از اینترنت در دسترس‌اند. [سیستم‌عامل‌های پشتیبانی‌شده](#technical-details).

```bash
curl -fSL https://github.com/xPROMSx/3x-ui-auto-nginx/releases/latest/download/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

پس از اجرای اسکریپت **1 — English** یا **2 — Русский** را انتخاب کنید. سپس منوی اصلی باز می‌شود:

- **1 — Installation:** راه‌اندازی سرور جدید یا نصب مجدد کامل.
- **2 — Change Domains:** تغییر دامنهٔ پنل، REALITY یا هر دو بدون نصب مجدد.
- **3 — Backups:** ایجاد، نمایش و بازیابی نسخه‌های پشتیبان.
- **4 — Telegram Web Proxy Manager:** اجرای مدیر مستقل پروکسی تلگرام یا نصب آن.
- **0 — Exit:** خروج.

برای استفاده از منو باید از یک ترمینال تعاملی SSH استفاده کنید.

<details>
<summary><strong>دریافت جایگزین — اگر GitHub Releases در دسترس نیست</strong></summary>

**شاخهٔ `main` برای توسعه استفاده می‌شود.** ممکن است شامل تغییراتی باشد که هنوز وارد انتشار پایدار نشده‌اند، از جمله قابلیت‌های به‌اندازهٔ کافی آزمایش‌نشده یا خطاها. برای نصب معمولی از نسخهٔ پایدار بالا استفاده کنید.

```bash
curl -fSL https://raw.githubusercontent.com/xPROMSx/3x-ui-auto-nginx/main/x-ui-latest.sh -o x-ui-latest.sh && bash x-ui-latest.sh
```

</details>

<a id="installation-vs-update"></a>

> [!CAUTION]
> **نصب به معنی به‌روزرسانی نیست!**
>
> اجرای دوبارهٔ اسکریپت **بدون پارامتر** فقط مدیر را باز می‌کند و سرور را دوباره نصب نمی‌کند. با این حال، گزینهٔ **Installation** برای VPS تازه یا نصب مجدد کامل است.
>
> اگر نصب قبلی شناسایی شود، اسکریپت دربارهٔ حذف داده‌های تحت مدیریت پروژه هشدار می‌دهد و تأیید دقیق **YES** را می‌خواهد. در نصب مجدد، پایگاه دادهٔ 3X-UI و پیکربندی nginx جایگزین می‌شوند. **ابتدا یک نسخهٔ پشتیبان را خارج از VPS نگه دارید.**
>
> **Change Domains** و **Backups** عملیات مستقلی هستند و پنل را دوباره نصب نمی‌کنند.

<details>
<summary><strong>چطور به‌روزرسانی کنیم؟</strong></summary>

- **3X-UI و Xray:** از ابزارهای داخلی پنل برای به‌روزرسانی استفاده کنید. ممکن است سازگاری نسخه‌های جدید با پیکربندی این پروژه هنوز تأیید نشده باشد.
- **3X-UI AUTO NGINX:** به‌روزرسانی مستقیم سیستم نصب‌شده پشتیبانی نمی‌شود. برای استفاده از امکانات مدیر جدید، اسکریپت فعلی را دانلود کنید و عملیات موردنیاز را انتخاب کنید؛ مدیر سازگاری نصب موجود را بررسی می‌کند.
- **Backup / Restore:** داده‌ها را ذخیره و بازیابی می‌کند، نه اینکه سیستم را به‌روزرسانی کند.

**فقط برای به‌روزرسانی گزینهٔ Installation را انتخاب نکنید!** nginx، هستهٔ Linux و بسته‌های سیستم را با ابزارهای سیستم‌عامل به‌روز کنید.

</details>

در ادامه تنظیماتی توضیح داده شده‌اند که پس از انتخاب **Installation** از منوی اصلی ارائه می‌شوند.

### 2. 🛰️ دامنهٔ VLESS REALITY

> `Enter the domain for VLESS REALITY:`

دامنهٔ دوم را برای REALITY وارد کنید. رکوردهای DNS هر دو دامنه باید به نشانی IP سرور VPS شما اشاره کنند.

<details>
<summary>ℹ️ پارامترهای اضافی اجرا</summary>

می‌توانید هر دو دامنه را از ابتدا در فرمان وارد کنید و نیازی به پاسخ تعاملی برای آن‌ها نباشد:

```bash
bash x-ui-latest.sh -subdomain panel.example.com -reality_domain reality.example.com
```

به‌جای `panel.example.com` و `reality.example.com` دامنه‌های خودتان را بگذارید. قابلیت‌های اختیاری همچنان هنگام نصب پرسیده می‌شوند.

</details>

### 3. 🔐 امنیت پیشرفتهٔ VPS

> `Enhance VPS security? [Y/n]:`

*پیشنهادشده برای کاربران کم‌تجربه · به‌صورت پیش‌فرض فعال (`Y`)*

نصب‌کننده Fail2ban را برای حفاظت SSH، DNS رمزگذاری‌شدهٔ سیستم (DoT) و به‌روزرسانی‌های امنیتی خودکار تنظیم می‌کند. اگر شرایط مناسب باشد، مستقل از انتخاب حفاظت اضافی، فایل swap با اندازهٔ ۱ GiB نیز می‌سازد.

**پیش از فعال‌کردن این گزینه توضیحات زیر را بخوانید**، به‌ویژه زمان‌بندی راه‌اندازی مجدد خودکار.

<details>
<summary>🔐 توضیحات کامل تنظیمات امنیتی</summary>

با انتخاب `Y` تنظیمات امنیتی اضافی فعال می‌شوند. پیکربندی swap مستقل از این انتخاب انجام می‌شود:

- **Swap با اندازهٔ ۱ GiB.** اگر swap فعال وجود نداشته باشد، سیستم فایل پشتیبانی شود و دست‌کم ۴ GiB فضای آزاد باشد، نصب‌کننده فایل swap را ایجاد و فعال می‌کند. تنظیمات swap موجود تغییر نمی‌کنند. اگر شرایط برقرار نباشد، این مرحله بدون توقف نصب رد می‌شود.
- **محافظت SSH — Fail2ban.** تعداد تلاش‌های ناموفق و تکراری ورود را با توجه به پورت‌های واقعی SSH محدود می‌کند. تنظیمات فعلی احراز هویت SSH تغییر نمی‌کنند.
- **DNS رمزگذاری‌شده (DoT).** سرورهای سراسری Cloudflare و Google از DNS-over-TLS اجباری از طریق `systemd-resolved` استفاده می‌کنند. مسیرهای DNS و دامنه‌های جست‌وجوی رابط‌ها و VPN حفظ می‌شوند؛ پرس‌وجوهای آن‌ها ممکن است بدون رمزگذاری باقی بمانند. اگر آماده‌سازی DoT شکست بخورد و DNS اصلی با موفقیت بازیابی شود، نصب بخش اصلی، Fail2ban و به‌روزرسانی‌های خودکار مستقل از DoT ادامه می‌یابد؛ نتیجهٔ نهایی خطا را اعلام می‌کند و کد خروج غیرصفر است.
- **به‌روزرسانی‌های امنیتی خودکار.** فهرست بسته‌ها ساعت 02:30 به‌روز و به‌روزرسانی‌های امنیتی ساعت 02:50 نصب می‌شوند.
- **راه‌اندازی مجدد خودکار — 04:38.** اگر پس از به‌روزرسانی نیاز به راه‌اندازی مجدد باشد، در ساعت تعیین‌شده انجام می‌شود، **حتی اگر کاربران اتصال فعال داشته باشند**. در نتیجه ممکن است ارتباط‌ها قطع شوند.

این ساعت‌ها براساس منطقهٔ زمانی محلی VPS هستند.

پیش از اعمال تغییرات، سازگاری تنظیمات فعلی بررسی می‌شود و در صورت شکست تنظیمات امنیتی، بازگردانی کنترل‌شده انجام می‌گیرد.

**مهم:** این گزینه ورود SSH با رمز عبور را غیرفعال نمی‌کند و جای مدیریت درست سرور را نمی‌گیرد. ابتدا ورود با کلید SSH را تنظیم و سپس احراز هویت با رمز عبور را خودتان غیرفعال کنید.

</details>

### 4. 🔗 VLESS XTLS Vision

> `Set up an additional VLESS TCP/TLS (XTLS Vision) connection? (requires a separate domain) [y/N]:`

*اتصال اضافی · به‌صورت پیش‌فرض غیرفعال (`N`)*

اتصال VLESS جایگزین مبتنی بر TLS که در صورت ناپایداری یا مسدود شدن REALITY در شبکهٔ شما می‌تواند مفید باشد. این اتصال به‌صورت پروفایلی مستقل در پنل 3X-UI ساخته می‌شود.

> [!IMPORTANT]
> **XTLS Vision به دامنهٔ سوم و مجزا نیاز دارد** که با دامنه‌های پنل و REALITY متفاوت باشد. رکورد DNS آن باید به IP سرور اشاره کند. گواهی HTTPS و مسیریابی nginx خودکار تنظیم می‌شوند.
>
> پس از انتخاب `Y` نصب‌کننده این دامنه را نیز می‌پرسد: `Enter the domain for VLESS TLS Vision (must differ from the panel and REALITY domains):`.

### 5. 🔑 Amnezia WG

> `Set up an additional AmneziaWG connection? [y/N]:`

*اتصال اضافی · به‌صورت پیش‌فرض غیرفعال (`N`)*

یک اتصال مستقل AmneziaWG در پنل 3X-UI ساخته می‌شود. به دامنهٔ اضافی نیاز نیست.

<details>
<summary>ℹ️ دربارهٔ Amnezia WG</summary>

نصب‌کننده AmneziaWG 3.1 را روی **UDP/8443** تنظیم می‌کند و قانون لازم UFW را خودکار اضافه می‌کند.

پس از نصب، کلاینت را در پنل 3X-UI بسازید و پیکربندی یا لینک `vpn://` را برای برنامهٔ سازگار Amnezia دریافت کنید.

نصب‌کننده اتصال سمت سرور را می‌سازد، اما کلاینت‌های AmneziaWG را خودکار ایجاد نمی‌کند.

پیکربندی و قانون لازم فایروال در **Backup / Restore v3** ذخیره می‌شوند.

</details>

<a id="xhttp-cdn"></a>

### 6. 🌐 VLESS + XHTTP برای CDN

> `Add an additional CDN-compatible XHTTP connection? [y/N]:`

*اتصال اضافی · به‌صورت پیش‌فرض نصب نمی‌شود (`N`)*

یک اتصال مستقل VLESS با انتقال XHTTP در حالت packet-up ساخته می‌شود که تنظیمات سرور آن برای استفاده از CDN آماده شده است. این اتصال در پنل 3X-UI به‌صورت غیرفعال ساخته می‌شود.

از دامنهٔ HTTPS فعلی پنل استفاده می‌شود و نیازی به دامنه یا گواهی اضافی نیست. پس از فعال‌سازی، اتصال بدون CDN نیز به‌صورت مستقیم قابل استفاده است.

برای استفاده از CDN، کاربر باید سرویس‌دهندهٔ خود را تنظیم کند و پارامترهای Host را در 3X-UI تغییر دهد. نصب‌کننده CDN را تنظیم نمی‌کند؛ فقط یک پروفایل آمادهٔ سرور برای استفاده و تنظیمات بعدی ارائه می‌دهد.

<a id="6--adguard-home--dns-over-https"></a>

### 7. 🛡️ AdGuard Home + DNS-over-HTTPS

> `Install and configure AdGuard Home? [y/N]:`

*سرور DNS اختیاری · به‌صورت پیش‌فرض غیرفعال (`N`)*

سرور DNS شخصی برای مسدود کردن تبلیغات و ردیاب‌ها، مدیریت کلاینت‌ها و پاسخ‌گویی به درخواست‌های DNS رمزگذاری‌شده.

<details>
<summary>ℹ️ دربارهٔ AdGuard Home و کنترل دسترسی</summary>

نیازی به دامنهٔ اضافی نیست.

پس از نصب این نشانی‌ها در دسترس خواهند بود:

- **پنل مدیریت AdGuard Home:** `https://panel.example.com/adg-.../` — مسیر تصادفی و اختصاصی.
- **DNS-over-HTTPS:** `https://panel.example.com/dns-query`.

پورت عمومی **53** برای TCP/UDP باز نمی‌شود. پیکربندی و داده‌های AdGuard Home در **Backup / Restore v3** ذخیره می‌شوند.

**⚠️ توصیهٔ امنیتی**

برای VPS شخصی، بهتر است برای هر دستگاه یک [ClientID](https://adguard-dns.io/kb/adguard-home/clients/#clientid) جداگانه بسازید.

در AdGuard Home به **تنظیمات ← تنظیمات DNS ← تنظیمات دسترسی ← کلاینت‌های مجاز** بروید و **فقط ClientIDها** را وارد کنید، نه آدرس‌های IP یا زیرشبکه‌ها را.

از آدرس‌های DoH به این شکل استفاده کنید:

`https://panel.example.com/dns-query/<ClientID>`

پس از تنظیم، درخواست‌های فاقد ClientID مجاز، از جمله درخواست‌های مسیر معمول `/dns-query`، رد خواهند شد.

شناسه‌های طولانی و تصادفی انتخاب کنید. [راهنمای رسمی امنیت AdGuard Home](https://adguard-dns.io/kb/adguard-home/running-securely/) را ببینید.

</details>

<a id="7--ساخت-خودکار-کلاینت-و-اشتراک"></a>

### 8. 👤 ساخت خودکار کلاینت و اشتراک

> `Create a client in 3X-UI and display a subscription link after installation? [Y/n]:`

*پیشنهادشده · به‌صورت پیش‌فرض فعال (`Y`)*

نصب‌کننده یک کلاینت در 3X-UI می‌سازد و برای اتصال‌های پیکربندی‌شده و پشتیبانی‌شده، لینک اشتراک HTTPS اختصاصی تولید می‌کند.

لینک اشتراک در گزارش پایانی نصب نمایش داده می‌شود. اگر این گزینه را نپذیرید، می‌توانید کلاینت‌ها را بعداً به‌صورت دستی در پنل بسازید.

---

در پایان، **آدرس پنل، نام کاربری و رمز عبور، نشانی ابزار تشخیص و لینک اشتراک** (در صورت انتخاب ساخت کلاینت) نمایش داده می‌شوند. اگر AdGuard Home نصب شود، آدرس مدیریت، رمز عبور و نشانی DoH آن نیز نمایش داده می‌شوند.

اگر پس از به‌روزرسانی سیستم‌عامل راه‌اندازی مجدد لازم باشد، نصب‌کننده اطلاع می‌دهد. **راه‌اندازی مجدد اولیه دستی است:** فرمان `sudo reboot` را اجرا کنید.

## 🌐 وب‌سایت‌های پوششی و HTTP/3

**وب‌سایت‌های کامل به‌جای صفحات سادهٔ موقت.** نصب تازه به‌صورت خودکار برای پنل و REALITY دو سایت چندصفحه‌ای متفاوت ایجاد می‌کند. شش قالب مدرن با ناوبری فعال، تصاویر اختصاصی و طراحی سازگار با موبایل در دسترس است. برای XTLS Vision اختیاری نیز سایت جداگانه‌ای انتخاب می‌شود.

**هر نصب ظاهر منحصربه‌فرد خود را دارد.** نام، رنگ‌بندی، تصاویر و متن‌ها به‌صورت خودکار شخصی‌سازی می‌شوند. طرح انتخاب‌شده هنگام Backup/Restore و تغییر دامنه‌ها حفظ می‌شود.

**Hysteria2 با پوشش HTTP/3.** درخواست‌های معمول HTTPS روی TCP و درخواست‌های HTTP/3 بدون احراز هویت روی UDP در دامنه REALITY، همان وب‌سایت کامل را دریافت می‌کنند. پنل و اشتراک‌ها از پوشش عمومی HTTP/3 جدا باقی می‌مانند.

## 🚀 پروفایل‌های اتصال

| اتصال | وضعیت |
| --- | :---: |
| VLESS + REALITY | ✅ فعال به‌صورت پیش‌فرض |
| VLESS + XHTTP | ✅ فعال به‌صورت پیش‌فرض |
| VLESS + XHTTP برای CDN | 🔧 اختیاری، غیرفعال |
| Hysteria2 | ✅ فعال به‌صورت پیش‌فرض |
| VLESS + WebSocket (TLS) | ◻️ غیرفعال به‌صورت پیش‌فرض |
| Trojan + gRPC | ◻️ غیرفعال به‌صورت پیش‌فرض |
| VLESS + XTLS Vision | 🔧 اختیاری |
| Amnezia WG | 🔧 اختیاری |

REALITY، XHTTP و Hysteria2 پس از نصب فعال‌اند. WebSocket TLS و Trojan gRPC ایجاد می‌شوند اما تا زمانی که آن‌ها را در پنل 3X-UI فعال نکنید، غیرفعال می‌مانند.

XTLS Vision، Amnezia WG و XHTTP برای CDN فقط در صورت انتخاب هنگام نصب اضافه می‌شوند. XHTTP برای CDN به‌صورت غیرفعال ساخته می‌شود و تا زمان فعال‌سازی و اتصال یک کلاینت، در اشتراک‌ها ظاهر نمی‌شود.

برای استفاده از اتصال‌ها، کلاینت‌ها را هنگام نصب به‌صورت خودکار یا در پنل به‌صورت دستی بسازید. کلاینت‌های Amnezia WG جداگانه ساخته می‌شوند.

سازگاری به برنامهٔ کلاینت و نسخهٔ آن بستگی دارد. برای XHTTP از طریق CDN، تنظیمات و محدودیت‌های سرویس‌دهندهٔ CDN نیز اهمیت دارند.

### اشتراک‌ها

اشتراک‌های استاندارد، JSON و **Mihomo / Clash** از طریق nginx و HTTPS ارائه می‌شوند. `provider=1` به‌جای پیکربندی کامل Clash، اشتراک اصلی را برای proxy providerها برمی‌گرداند.


<a id="change-domains"></a>

## 🌐 تغییر دامنه‌ها

در منوی اصلی گزینهٔ **2 — Change Domains** را انتخاب کنید. می‌توانید دامنهٔ پنل، REALITY یا هر دو را بدون نصب مجدد تغییر دهید. رکوردهای DNS جدید باید به VPS اشاره کنند و برای صدور گواهی، پورت TCP/80 در دسترس باشد. دامنه‌ها باید با یکدیگر و دامنهٔ Vision متفاوت باشند.

پیش از هر تغییر، یک Backup v3 کامل به‌صورت خودکار ساخته می‌شود. کلاینت‌ها، کلیدها، تنظیمات و آمار ترافیک حفظ می‌شوند. دامنهٔ Vision تغییر نمی‌کند. پس از تغییر ممکن است لازم باشد نشانی اشتراک‌ها و تنظیمات کلاینت را به‌روزرسانی کنید.

فقط نصب‌های شناخته‌شدهٔ پروژه، از جمله نصب‌های سازگار v2.1.7، پشتیبانی می‌شوند. در صورت بروز خطا، **نسخه‌های پشتیبان و اطلاعات بازیابی را حذف نکنید**. اگر `ROLLBACK_UNVERIFIED` نمایش داده شد، متوقف شوید و اطلاعات تشخیص خطا را نگه دارید. [جزئیات، محدودیت‌ها و بازیابی](docs/MANAGER.md#change-domains).

## 💾 پشتیبان‌گیری و بازیابی

در منوی اصلی **3 — Backups** را باز کنید تا نسخهٔ پشتیبان بسازید، فهرست آرشیوها را ببینید یا Restore را اجرا کنید. می‌توانید پس از نصب مجدد سیستم‌عامل یا برای انتقال به VPS دیگر از نسخهٔ پشتیبان استفاده کنید. برای بازیابی، سیستم‌عامل، نسخهٔ آن و معماری پردازنده باید با اطلاعات نسخهٔ پشتیبان یکسان باشند.

دستورات خط فرمان زیر نیز با دسترسی root در دسترس‌اند:

```bash
# ایجاد نسخه پشتیبان
x-ui-backup backup

# نمایش نسخه‌های پشتیبان
x-ui-backup list

# بازیابی یک نسخه پشتیبان
x-ui-backup restore /var/backups/x-ui/<archive>.tar.gz
```

فایل‌های پشتیبان در `/var/backups/x-ui/` ذخیره می‌شوند.

> **نسخه‌های پشتیبان حاوی اطلاعات حساس‌اند:** پایگاه داده کاربران، گذرواژه‌ها و کلیدهای خصوصی گواهی‌ها. یک نسخه را **خارج از VPS** نگه دارید و فقط فایل‌های پشتیبان قابل اعتماد را بازیابی کنید.

[بازیابی روی VPS جدید](#restore-on-new-vps).

## 🔐 امنیت

رابط‌های سرویس‌ها مستقیماً در اینترنت منتشر نمی‌شوند. پنل، اشتراک‌ها و سرویس‌های جانبی از طریق nginx و HTTPS در دسترس‌اند و پورت‌های داخلی فقط روی میزبان محلی گوش می‌دهند.


**مطمئن نیستید چطور از VPS خود محافظت کنید؟** هنگام نصب می‌توانید تنظیمات امنیتی پیشرفته را فعال کنید تا محافظت SSH در برابر تلاش‌های ورود، DNS رمزگذاری‌شده و به‌روزرسانی‌های امنیتی خودکار تنظیم شوند. پیش از فعال‌سازی، توضیحات و برنامهٔ راه‌اندازی مجدد شبانه را در بخش **شروع سریع** بخوانید.

**مهم:** دسترسی به خود سرور را نیز ایمن کنید. از کلیدهای SSH استفاده کنید و پس از اطمینان از امکان ورود با کلید، ورود با رمز عبور را غیرفعال کنید. نصب‌کننده این کار را خودکار انجام نمی‌دهد.

## ✈️ Telegram Web Proxy Manager

[Telegram Web Proxy Manager](https://github.com/xPROMSx/telegram-web-proxy-manager) پروژه‌ای مستقل برای راه‌اندازی Telegram WEB Proxy شخصی با HTTPS، وب‌سایت پوششی و به‌روزرسانی همراه با امکان بازگشت به نسخهٔ قبلی است.

**TWPM بخشی از نصب پیش‌فرض 3X-UI نیست.** گزینهٔ 4 منوی اصلی اجازه می‌دهد آن را اجرا کنید یا پس از تأیید، نصب مستقل آن را آغاز کنید. مدیریت دو پروژه مستقل است.

<a id="technical-details"></a>

## ⚙️ جزئیات فنی و سازگاری

- **سیستم‌عامل‌ها:** Ubuntu 24.04، Ubuntu 26.04 و Debian 13.
- **UFW:** پورت‌های 80/tcp، 443/tcp و 443/udp را مجاز می‌کند (با انتخاب AmneziaWG، پورت 8443/udp نیز افزوده می‌شود). هنگام Installation، UFW تنها پس از بررسی دسترسی SSH فعال می‌شود؛ در غیر این صورت با هشدار غیرفعال می‌ماند. پس از Restore از طریق منو، UFW **فقط با انتخاب صریح شما** و گذراندن بررسی‌های ایمنی قابل فعال‌سازی است. دستور `x-ui-backup restore`، UFW را فعال نمی‌کند.
- **گواهی‌ها:** گواهی‌های Let's Encrypt با روش webroot و تایمر استاندارد `certbot.timer` بدون توقف nginx تمدید می‌شوند.
- **نسخه 3x-ui:** به‌صورت پیش‌فرض جدیدترین نسخه‌ای نصب می‌شود که سازگاری آن با 3X-UI AUTO NGINX به‌دقت آزمایش شده است؛ این نسخه لزوماً آخرین انتشار رسمی 3x-ui نیست. پس از نصب می‌توانید 3x-ui را با روش به‌روزرسانی داخلی خودش ارتقا دهید، اما ممکن است سازگاری نسخه جدید با پیکربندی فعلی هنوز تأیید نشده باشد. همچنین می‌توانید با `-version <tag>` نسخه پایدار دیگری را انتخاب کنید (حداقل نسخه پشتیبانی‌شده v3.8.0 است)؛ نصب‌کننده درباره تأیید نشدن سازگاری هشدار می‌دهد.

<a id="restore-on-new-vps"></a>

### بازیابی روی VPS جدید

سیستم‌عامل، نسخه آن و معماری پردازنده باید با نسخه پشتیبان مطابقت داشته باشند. اگر آدرس IP سرور VPS تغییر کرد، رکوردهای DNS دامنه‌ها را به‌روزرسانی کنید. **اسکریپت `x-ui-latest.sh` را اجرا نکنید**؛ فقط ابزار بازیابی را نصب کرده و یک آرشیو معتبر را بازیابی کنید:

```bash
curl -fSL https://raw.githubusercontent.com/xPROMSx/3x-ui-auto-nginx/main/assets/backup/x-ui-backup.sh -o /tmp/x-ui-backup
install -o root -g root -m 0755 /tmp/x-ui-backup /usr/local/bin/x-ui-backup
rm -f /tmp/x-ui-backup
x-ui-backup restore /root/<archive>.tar.gz
```

SSH، تنظیمات سیستم‌عامل و فایروال پایه همچنان بر عهده مدیر سرور است. برای آرشیوهای v2 باید از ابزار نسخه قدیمی متناظر استفاده شود.
